# Adopt Grok-first administrative autonomy

The Personal Prototype will add a Fresh-Passkey-activated Administrative Autonomy Policy that remains active until suspended and lets confirmed Durable Tasks choose their own Operation plans without per-command approval. The first general provider will be the pinned, subscription-authenticated Grok Build CLI in always-approve mode: separate Code and Research Subagent identities share credential custody but not authority, Code may inspect repository contents including repository-contained secrets while using brokers for dependencies and external effects, and Research may use the public internet plus typed read-only Agent Host observations to create primary-source Research Findings. Provider disclosure is accepted, but designated host credential stores, raw administrative credentials, and durable raw provider output remain outside Subagent access.

Policy-authorized discovery may register every current or future repository on the Agent Host, leave existing checkouts and dirty work untouched, and create one isolated worktree, branch, and pull request per affected repository. A distinct Administrative Publisher App may publish and update task branches across the owner's repositories with repository-narrowed tokens, while a Repository Administration Broker may create private repositories and install standard production-branch rules. Neither boundary can approve, merge, close, weaken rules, write a production ref, bypass checks, or deploy; Human Merge remains the only production-branch authorization, and automatic Promotion still requires an activated Deployment Contract.

Administrative effects remain brokered rather than giving model-generated commands an arbitrary root shell. The broker may perform typed production observation and reversible service, package, device, reboot, Live Patch, and Host Patch Operations; ad hoc production-data mutation is excluded. Live and Host Patches arm independent health checks and a 30-minute rollback before mutation, and their changes must become isolated pull requests or be removed. Destructive host or external-account outcomes must be named in Task Confirmation. Administrative mutations are serialized, read-only Research may run concurrently, active execution is bounded to six hours, and Administrative Suspension blocks new effects, activates armed rollbacks, and preserves branches and evidence.

This decision supersedes ADR-0011's explicit-only registration rule, ADR-0023's one-Subagent-global concurrency rule, and ADR-0024's exclusion of unrelated repositories and all repository-contained secrets. Their remaining provenance, structured-Delegation, provider-identity, and credential-isolation decisions continue to apply. Fresh-Passkey authority expansion, Brokered Secret Use, Human Merge, and non-self-authorizing Promotion remain unchanged. The owner accepts the high-risk choice to activate this policy without first demonstrating a whole-host DigitalOcean restore; snapshots are not treated as reversing credential disclosure or external effects.

Delivery remains vertical: first repair natural Task Confirmation and durable telephone-provider failure handling while completing the existing narrow Keeplore trial; then add Grok research/code profiles, repository discovery, branch-and-PR publication, evidence, Stop, and Administrative Suspension; finally add typed host administration and Live/Host Patches through a private Configuration Repository.
