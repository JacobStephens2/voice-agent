# Record what ended a failed Delegation

Three consecutive Keeplore Delegations failed inside the restricted Codex sandbox and the only account of any of them was one sentence the restricted model wrote about itself. The executor bound its caught error and used it only to test for a stop request, the Subagent Runner counted the executor's standard error and discarded it, the evidence directory stayed empty, and the model workspace was removed in a `finally` before anyone could look at it. A Delegation Result now carries the failure that ended it — the error's type, its bounded message, the failure kind, and the paths of the evidence retained for it — and the Subagent Runner forwards the executor's own standard error to the Agent Host journal. A failed run keeps Restricted Runner Evidence under its `0700` evidence directory: the restricted runner's exit status and standard error — including the partial output of a run its own output or time bound stopped — and a copy of the model workspace as it stood when the run ended. Evidence that cannot be written is reported on the same journal rather than lost in silence.

The failure kind separates a sandbox that never started from a model that ran and declined. `bwrap` reports a mount, namespace, or Landlock setup failure on its own standard error before the model process exists, so a non-zero runner exit whose output carries those markers is recorded as a sandbox initialization failure, and a model that ran and reported no candidate is recorded as a declined run. Without that distinction both arrive as the same empty Delegation Result, which is the reason a host session was needed to reach a fault the model had described three times.

The retained evidence is the runner's own output and the copied workspace, and neither can carry a telephone transcript: a Delegation Brief excludes raw voice transcripts by construction, the model workspace holds only the reference and editable files copied out of the Delegated Worktree, and the runner evidence record has no field for anything else. Policy rejects a Delegation Result whose failure evidence names a path outside its own evidence directory, and a completed Delegation may report no failure at all.

## Consequences

An Evidence Record excludes raw command output, so this retention is the deliberate debugging exception that definition already names, kept out of the Evidence Record and inside the Delegation's evidence directory. The retained standard error is bounded to its last 64,000 bytes and marked when truncated; a fault described only in earlier output is lost. The copied model workspace is as large as whatever the sandboxed model wrote, and it accumulates one copy per failed Delegation until an Evidence Lifecycle Policy expires it. Retention is best effort: a directory that cannot be written loses the evidence rather than replacing the failure the Delegation Result reports.
