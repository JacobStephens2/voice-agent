# Bootstrap authority and credentials out of band

Initial authority will be established by a short-lived, single-use Bootstrap Code generated through the owner's existing SSH access and entered at `voice.stephens.page`. Bootstrap enrollment is permanently disabled after two passkeys and Recovery Codes exist; later loss of authenticators follows offline recovery rather than reopening bootstrap. A separate human-run setup wizard places provider credentials consumed on the Agent Host into distinct root-owned sources and exposes each service only to its required credentials through systemd. Telnyx SIP credentials are a provider-to-provider exception: they remain only in Telnyx and LiveKit Cloud because no Agent Host process consumes them, and LiveKit sends the credential username in the initial outbound SIP INVITE. Provider credentials are never accepted through voice, the PWA, repository files, shell history, or general Subagent environments.
