# Pin and prove the Grok runner before it works

ADR-0048 makes the subscription-authenticated Grok Build CLI the only MVP provider for Administrative Autonomy, and `docs/research/grok-subagent-mvp.md` establishes that its headless contract - `--prompt-file`, `--output-format json`, `--json-schema`, `--always-approve`, `--max-turns`, `--no-auto-update`, a named sandbox profile - is a first-party interface rather than an inference. What that research also establishes is that a cached Grok login takes precedence over `XAI_API_KEY`, that a process able to read `auth.json` can spend the owner's subscription, and that headless usage fields are provider-dependent. A provider with those properties cannot be enrolled by logging in and calling it; it is enrolled by pinning exactly which bytes may run, proving one real subscription-backed execution against that pin, and recording that proof so a later build cannot inherit it.

The pin is a reviewed version, a SHA-256 digest, and the one configuration source this build reads, all recorded together in a root-managed file. The configuration path belongs in the pin rather than in a constant because a provider release may move where it reads system configuration, and enrollment is where that path is established from the runner's own `inspect` output. Before every accepted run the fixed executor re-reads the binary's digest, `grok inspect --json`, and the pinned configuration itself, and pauses the Durable Task if the runner self-updated, authenticates through anything other than the subscription, has an API key available, selects another model, left always-approve off, names another sandbox profile, reads configuration from any source outside the pinned one, declares an MCP server, plugin, or skill, or ships a sandbox profile that has stopped denying a Credential Custody Boundary store. That last check exists because `inspect` names the profile in force without quoting its rules back: a profile that quietly lost a deny rule would otherwise pass everything else. An inspection this contract cannot read at all is drift too. The check is deliberately unforgiving because it is cheap and because every boundary below it is stated in the configuration it validates: a repository that could introduce a same-named MCP server, or a release that renamed a field, would otherwise remove a boundary without removing the appearance of one.

Model execution and provider authentication are separate identities. `voice-grok-auth` owns the OAuth refresh credential; `voice-grok` owns the model process, an ephemeral per-run `GROK_HOME` removed once evidence is extracted, and an environment built as an allowlist rather than a filtered copy of the service's own. The runner obtains a short-lived access token through a root-owned broker the model's sandbox denies, which crosses to the custody identity under a sudoers rule narrowed to one command with no arguments; the helper on the far side refuses to run as anyone else. Because model-selected commands share the runner's identity, file permissions alone would not keep that token from them - a process able to attach to the runner can read it out of memory - so the host also sets Yama's restricted ptrace scope, under which the model's shell, being a descendant of the runner, cannot trace it. The Credential Custody Boundary - the provider auth store, the brokers, the publisher, the evidence store, root's and the Voice Agent's own state - is stated once in this codebase and enforced twice: the executor refuses to stage a run inside it, and the reviewed sandbox profile and the systemd unit both deny it. An inherited `XAI_API_KEY` does not get stripped; it refuses the run, because an API key on this identity means the metered route was provisioned somewhere and the MVP's whole claim is that it cannot be reached.

Every ending is named. A run the provider refused for authentication, entitlement, quota, or contract drift pauses the Durable Task; malformed output, an exhausted turn bound, a time bound, and a runner that failed for its own reasons fail it; a signal stops it. There is no ending that selects another provider or another billing route, and no ending that leaves a Delegation root reset, stashed, cleaned, or deleted - completed commits and unfinished work survive all four, and the one place this executor invokes Git refuses the subcommands that would discard them. Durable evidence holds the provider-reported model beside the logical selector, the runner pin, the authentication route, session and request identity, stop reason, token usage, and whether the provider marked that usage incomplete. An absent monetary cost is recorded as unknown rather than as zero, because a run the owner's subscription paid for is not free.

The proof is enforced, not filed. The executor reads the enrollment record before any run whose brief declares `work`, and pauses unless that record is accepted for the exact pin installed; only the `contract-test` purpose is exempt, because it is the run that produces the proof. An unreadable or absent record is an absent proof. The record itself is evaluated from its most recent runner pin forward: the attended device authorization, one completed subscription-backed run recorded against that exact pin, a Credential Custody Boundary probe that read nothing - enumerated from the same boundary list the executor and the sandbox profile use, so a store added later is probed without anyone remembering to - a drill for each of the eight failure conditions ending in the state that condition must reach, and a stop drill that preserved work. Pinning a new build discards every proof belonging to the old one, so a provider upgrade cannot activate until the contract passes again. This is why the record is keyed on the pin rather than on the provider.

## Correction after contact with the runner

Everything above was designed against a research note written from documentation. Installing grok 1.0.13 on the Agent Host disproved a substantial part of the plumbing, and the corrections change what this decision claims rather than only how it is spelled. The runner reads its non-overridable policy from a `requirements` configuration layer, reported by `inspect` alongside `managed` and `user` layers; the executor now requires that layer to be the only one in effect. The fields the drift check reads are the ones the binary emits, and the four it used to read - self-update, authentication source, model selector, approval mode - have no counterpart at any spelling. Three of those are fixed on the command line, where a project directory cannot reach them; the fourth is better than it was, because `loginPolicy.apiKeyAuthDisabled` is policy the runner enforces rather than the absence of a variable in one process's environment.

Two claims are weaker than this decision originally made them. xAI publishes no checksum, signature, or provenance for its artifacts, so the digest attests that the runner has not changed since it was reviewed on this host and attests nothing about the download; two independent fetch routes producing byte-identical binaries is the strongest corroboration available. And the sandbox cannot hold the Credential Custody Boundary: `restrict_network` and every `deny` rule make the runner refuse to start here, because after entering Bubblewrap it re-opens each read-deny path to confirm the mask took effect, and a path the executor identity cannot open at all answers `Permission denied` - which it reads as an unenforced deny list. Every store in the boundary is root-owned or 0700 for exactly the reason it is in the boundary. Custody is therefore held by the executor identity's own permissions and the systemd unit, and the sandbox holds workspace confinement. The child-process network restriction this decision assumed is currently unavailable, which is a real reduction in what a Delegation is confined to and is tracked rather than papered over.

## Consequences

Grok cannot run at all until the enrollment record is accepted, and cannot keep running through an upgrade. That is the intended cost: the alternative is a self-updating binary holding a consumer credential inside an always-approve loop. The reviewed inspection field names are confirmed against the pinned runner during enrollment rather than taken from documentation, and a runner release that renames one of them pauses work instead of silently dropping a boundary - a false pause is recoverable by review, a silently dropped boundary is not.

Nothing here grants repository discovery, publication, brokered administrative effects, or the Research profile. This decision covers one bounded structured execution under the boundaries ADR-0048 requires; the multi-repository worktree, branch, and pull-request path and the typed host Operations remain the later slices ADR-0048 describes, and they inherit this pin, this custody boundary, and these endings rather than restating them.
