# Say why the publisher refused, on the host alone

The Keeplore publisher is the component that trusts nothing and re-derives everything: it re-parses the request, re-reads the Registered Delegation, re-reads the Repository Policy Observation, re-inspects the Delegated Worktree, and re-observes the pull request it created. That makes it the component with the most distinct refusal reasons, and it discarded every one of them. One catch around the whole request answered `422 publication-refused` and wrote nothing, so "Keeplore publication policy is absent or stale", "Keeplore production rules do not preserve Human Merge", "Keeplore production-rule bypass is not currently attested", and "Keeplore GitHub App grant is not the reviewed installation" were indistinguishable from each other and from a candidate the publisher judged unclean. Diagnosing one meant reading the publisher's source, enumerating every condition that can throw, and comparing each by hand against live host state — after a telephone call, a model run, PHPUnit, and screenshot capture had all already succeeded.

The publisher now writes one journal line for every refusal, carrying the reason the check itself raised, and answers with a refusal code alone. The reason stays on the Agent Host because of what these reasons are: they describe production branch rules, GitHub App grants, and a Delegation's registered assignment, which is exactly the host state the Subagent that asked to publish must not learn. The Credential Custody Boundary is not weakened to make the boundary diagnosable. What crosses the socket is the phase that refused — `request`, `candidate`, `policy`, or `publication` — which lets the runner report that a boundary refused rather than that its candidate was rejected, without saying which boundary or what it observed.

A fault the publisher raises before reaching any check is coded `unattributed` rather than folded into the last phase, so a defect in this service is never reported as a refusal of a candidate that was never judged. The code names a phase rather than a check for the same reason. A per-check code would be the reason in another alphabet, readable by anyone who can read the publisher's source, which the Subagent can. A phase is coarse enough to disclose nothing beyond the fact that the publisher, not the candidate, was at fault, and specific enough to route the operator to the right journal line.

This decision extends ADR-0051's rule that a failed Delegation records what ended it to the one component whose account of itself was previously empty, and follows ADR-0050's operator log envelope so the publisher's line and the worker's land in one journal in one shape. It repairs the same defect as the trial's `codex login status` check: a check that exits without saying what it saw.

## Consequences

An operator diagnosing a refused publication reads one journal line instead of the publisher's source. The Delegation Result and the Evidence Record gain a coarse code and no reason, so a refusal is now attributable to the boundary or the candidate from the Delegation Result alone, and still requires host access to resolve further — which is the intended cost of keeping branch-rule and App-grant state on the host.

The guarantee rests on the publisher's throw sites continuing to author their own messages. Every reason journalled here is a fixed string written in this repository or the bounded output of a command it spawned, never a value from the request — which is why the request body's own parse error is replaced by a fixed string before it is raised, since the JSON parser quotes the bytes it rejected. One value from the request does reach the line: the Delegation identity the request claimed, journalled only when it already matches the registered shape and before any check has confirmed that Delegation exists. It is bounded to that charset and length, so a rejected request cannot forge a journal line, but the line names a claimed identity rather than a verified one. A future check that interpolates untrusted input into its message would put that input in the operator's journal, which is a weaker exposure than the response but still a change in what this line may contain.

Because the publisher is installed as one file and started directly by systemd, it carries its own copy of the log envelope and of the message sanitizer rather than importing the worker's, and it names the refusal codes in its own union rather than reading the contract the runner validates against. Divergence is now possible in three places: two log shapes in one journal, two sanitizers, and a code the publisher emits that the contract does not name — which the runner would report as a bare status rather than as the phase that refused.
