# Attribute a telephone fault to the stage that raised it

One catch in the worker wrapped a whole finalized turn — the interpretation provider's call and every action taken after it — and reported anything that escaped as a failure of the interpretation provider. A fault raised while recording speech timing, appending evidence, or breaking one of this system's own invariants was therefore logged and recorded as an OpenAI outage, which is what sent three rounds of diagnosis at a provider that had not failed while the caller heard the answer complete and the line drop. The turn pipeline now reports under its own failure stage, `agent`, whose provider is the Voice Agent itself, and only the interpretation provider's own call is marked as the interpretation stage wherever in the pipeline its error surfaces. A bounded fault at the new stage keeps the recovery every other stage has: one Bounded Provider Retry that replays the finalized turn, then the prerecorded response and the end of the call.

The rule for what a failure may say about itself is inverted with it. A message was previously kept only at the stages whose provider never receives the caller's words, so a Telephone Session Fault had to be marked one invariant at a time to stay diagnosable and an unmarked error stayed anonymous. A message is now withheld only where it is a provider's account of something the caller said: an error raised by a speech or interpretation SDK, a framework report of unexpected model behaviour, a schema validation error naming the value it rejected, or any error the framework reported on a named provider's behalf through a session error event — and then only at the recognition and interpretation stages. Everything else in this path is text authored in this repository, and every such site raises a fixed string that carries nothing from the call.

This decision supersedes ADR-0050's rule for which messages are withheld and extends ADR-0049's enumeration of what a Bounded Provider Retry may replay. ADR-0050's operator log line, its sanitization, and ADR-0044's fail-closed ending remain unchanged, and the Evidence Record still carries no description of the fault.

## Consequences

An operator's journal now names a fault this system raised, wherever in the turn pipeline it happened, without that fault first having to be marked. The cost is that the guarantee has moved: it no longer rests on an allowlist of stages but on every throw site in the telephone path keeping a transcript, a spoken response, and a caller identity out of its message, and on provider errors continuing to arrive either as their SDK's own classes or through the framework's session error events. A provider library that raises a bare `Error` on some path the framework does not report as a session error would have its message logged at the recognition or interpretation stage.

`agent` joins the durable provider-failure stages, so an Evidence Record, a boundary failure counter, and the `voice_agent_telephone_provider_failures_total` metric can all name it. Faults that were previously counted and recorded against `coordinator` and OpenAI now appear there instead, which is a discontinuity in that series rather than a change to any record already written.
