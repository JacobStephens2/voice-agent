# Refuse an unrecognized speech model before the worker takes a call

The model the Voice Agent recognizes speech with was a literal written out twice — once for the conversation transcriber and once for the machine detector's — so when AssemblyAI stalled on 2026-08-25 and Telephone Session `baf1ea06-f9f2-48e9-b15f-58d4061b6ff6` ended `provider-failure` after 61.8s, there was no setting to move off the stalled gateway. The remedy is a Recognized Speech Model: a set this system carries, each entry naming its model, the provider identity recorded against its stage, and the options that provider's own gateway accepts. A setting is a choice from that set rather than a free string, because a validated `provider/model` shape cannot tell a real model from a mistyped one and would deliver its refusal as a provider error in the middle of a call — the fault this decision exists to prevent.

The setting is resolved once when the agent worker's process starts, not when it takes a job, and a setting naming anything outside the set ends that process rather than the call. Every other setting in this path is read inside `defineAgent`'s entry, so a malformed one today survives Promotion, reports a healthy Release, and then fails callers one at a time until a human notices. A recognition model reaches the Agent Host only through a Human Merge and a Promotion, and a Promotion Attempt already runs post-Promotion health verification and rolls back automatically when it fails; refusing at process start puts a misconfigured model in front of that machinery, so it becomes a rejected Release instead of a live outage. The cost is deliberate: an operator who mistypes the setting takes the worker down completely rather than degrading it, which is the louder of the two failures and the one that reverses itself.

Nothing switches provider during a call. ADR-0049's single Bounded Provider Retry, ADR-0044's fail-closed ending, and ADR-0052's attribution of a fault to the stage that raised it are unchanged, and `CONTEXT.md` still lists automatic provider failover as vocabulary to avoid. What changes is that the provider recorded against a speech stage is read from the entry in use rather than inferred from the stage, so an operator who moves off a stalled gateway is not reading `provider=assemblyai` against a fault a different provider raised.

## Consequences

The provider recorded for a recognition fault now follows the configured entry, and the operational rollup folds a provider it does not enumerate into `other` rather than misreporting it, so moving to the researched fallback needs no schema migration. The entry's model also appears on the provider-failure and speech-timing events, which is what lets a recorded `stage=stt` fault be read against the model actually in use; a finalized turn still carries only its stage's provider, because adding the model to every turn answers no question an operator asks.

The machine detector's transcriber reads the same setting, and since #131 its faults are raised at the recognition stage rather than through `TelephoneSetupProviderError("coordinator")`, so the provider and model recorded for a detection-time recognition failure follow the configured entry as the conversation's do. Its transcriber is still left unbiased: a voicemail greeting carries none of the domain keyterms, so only the model is configured there.

One thing is left as it is and tracked separately. The drift from the researched `assemblyai/universal-3-5-pro` to `assemblyai/universal-streaming-multilingual` was never written down anywhere — an unrecorded model change of exactly the kind this set exists to make visible, now tracked as #134.
