# Refuse a Keeplore source commit that already carries the fix

The Keeplore Button Trial accepts a candidate only as the registered `ui/style.css` plus one appended table-only rule, so a registered source commit whose stylesheet already ends with that rule is unwinnable by construction: restricted Codex has nothing left to append, and `assertTableOnlyCandidate` refuses the empty addition. Delegation `a909edd2-7b36-412d-97e9-5351aec18263` spent a telephone call, a 24,698-token Codex run, and an operator's review to learn that, against `4cc29d1debf154fb5becf383e3130b1366e71a31`, the default the wizard offers, which carries the rule Keeplore PR #4 merged.

The trial now reads the pinned commit's stylesheet before it asks for the call. `readTrailingTableOnlyRule` puts the untouched stylesheet through the same acceptance test a model's candidate faces, so a commit is refused as already satisfied only for a rule the trial would itself have accepted, and the refusal names the commit, prints the rule, and points at the newest first-parent ancestor whose `ui/style.css` does not end with it. The refusal precedes the service restart that hands the pinned commit to the Subagent, so a refused trial changes no state. The candidate guard's own "absent or too large" wording is now two failures with two causes: an addition that is absent, and one that exceeds the registered byte limit.
