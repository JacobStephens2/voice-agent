# Describe a bounded provider failure without the caller's words

An Evidence Record excludes raw provider output, so a Telephone Session that ended on a bounded provider fault recorded only its failing stage and failure class and nothing that described the fault itself; five consecutive dropped calls left an `end_reason` in durable boundary state as their only trace. The operator's journal on the Agent Host now carries one line for every bounded provider failure, naming the stage, the provider, the recovery, and a sanitized description of the error. A provider's own message is kept only where that provider never receives the caller's words — speech synthesis, which is given the agent's own text, and session setup, which is given neither. Recognition is handed the caller's audio and interpretation is handed the resulting transcript in its prompt, so a message from either may quote the caller back and is withheld; the error's type, status, and code are kept at every stage. The Evidence Record is unchanged.

A Telephone Session Fault is exempt from that restriction because it is not a provider's account of anything: it is a broken invariant this system raises in fixed text authored here, so its message is logged at every stage, and every site that raises one must keep its message free of a transcript, a spoken response, or a caller identity. The distinction is what lets an operator separate our own fault from a provider outage without placing another call — the failure that prompted this was attributed to the interpretation provider through three rounds of diagnosis while being neither a provider's error nor an invariant that had been marked.

## Consequences

An ordinary error raised outside the marked set still logs no message at the recognition and interpretation stages. That is the deliberate cost of defaulting to the caller's privacy, and it means a fault escaping an unmarked path stays unnamed until the path is marked or the rule is narrowed to withhold messages only from errors a provider SDK itself raised.
